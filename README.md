# Flight Data Anomaly Detector
#### Video Demo: https://youtu.be/fhf7qar22RY?si=Lsyp2kwIOBnBEkUX
#### Description:

Flight Data Anomaly Detector is a Python CLI tool I developed to analyze flight logs. The program parses a CSV file, validates the timestamps, and automatically detects rule violations, such as exceeding max speed or falling below minimum altitude limits.
I built this tool to automate the review process and avoid human errors while reading flight data. If the program catches any issues, it displays a formatted table in the terminal and exports the results to a JSON file for further use.
## Files and Architecture

The project is structured into three main files to maintain clean architecture and testability:

*   **`project.py`:** This is the main file of the project. It uses argparse so you can set custom speed and altitude limits right from the command line. Besides the main function, it includes five custom functions:
    *   `read_flight_data(log_file)`: Reads flight records from the CSV file using `csv.DictReader`. It uses a generator with `yield` to process records one at a time.
    *   `is_valid(timestamp)`: Uses regular expressions (`re`) to ensure the incoming timestamp strictly follows the "YYYY-MM-DD HH:MM:SS" format.
    *   `detect_anomalies(data_generator, max_speed, min_altitude)`: Iterates through the parsed flight data, checking for valid timestamps and applying the physics rules (speed and altitude limits). It flags any problematic rows.
    *   `generate_report(anomalies)`: Displays the detected anomalies in a formatted table in the terminal using the `tabulate` library.
    *   `convert_json(anomalies, filename)`: Takes the list of detected anomalies and securely writes them into a structured JSON file.
*   **`test_project.py`:** Contains the unit tests for the application. It uses the `pytest` framework to independently test `is_valid`, `detect_anomalies`, and `convert_json` functions using mock data. This ensures the logic holds up against edge cases (e.g., malformed strings, extreme values).
*   **`requirements.txt`:** Lists the external dependencies required to run the project, specifically the `tabulate` library used for rendering the terminal output.

## Design Choices

During the development of this project, several design choices were made to optimize performance and readability.

To prevent memory crashes with huge flight logs, read_flight_data() uses a generator (yield) to process the CSV file row by row instead of loading the whole thing at once. Also, I read the data as Python dictionaries so I could easily call things like (`row["speed"]`) instead of dealing with confusing list indexes.

I decided to use the `tabulate` library for the terminal output. Regular print statements tend to get messy and misaligned when printing data. `tabulate` automatically formats everything into a clean, easy-to-read grid.

Finally, for data export, JSON was chosen over writing to a simple text file. JSON is the industry standard for API communication and data storage, meaning the anomaly report generated by this tool can be easily ingested by web dashboards, databases, or other microservices in a real-world scenario.

## 💻 Tech Stack
- **Language:** Python 3
- **Libraries:** `re` (Regex), `json`, `csv`, `argparse`, `pytest`, `tabulate`

## 🛠️ How to Run
1. Install the required dependencies:
   ```bash
   pip install -r requirements.txt
   ```
2. Run the main program:
   ```bash
   python project.py
   ```
3. Run the unit tests:
   ```bash
   pytest test_project.py
   ```
